# 性能诊断范围

[模块导航](README.md) · [质量工具链](quality-tooling.md)

当前仓库聚焦工程、模型导入、几何 / 网格处理和 VTK 行为验证，不维护独立 CPU/GPU 基准、性能 runner、自动采样或历史测量基线。

出现可复现的启动延迟、加载卡顿、内存增长或渲染问题时，先建立独立任务，固定真实输入、机器、工具链、构建配置及触发操作，再决定所需的测量工具和最小接线。未实施的工具与命令不作为现有入口。

计时应区分文件读取、解析、快照转换、GUI 调度、GPU 完成与显示器呈现；内存应区分资产容量、堆分配与进程 RSS。比较必须使用同一环境、输入和测量终点，报告限制，不从单个 CPU 样本推断 GPU 帧率。

诊断代码只保留实际消费者所需部分；任务结束时删除临时采样设施。行为回归继续通过实际工程、失败恢复、资源释放和真实窗口验收，不引入性能数值门禁。
