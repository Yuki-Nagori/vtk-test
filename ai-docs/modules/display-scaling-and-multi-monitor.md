# 高 DPI 缩放与多显示屏（规划）

[模块导航](README.md) · [QML 规范](../standards/qml.md) · [Qt 规范](../standards/qt.md)

## 为什么现在就要设计

需要操心。CAE 界面同时包含 QML 控件、VTK 视口、截图/导出和可持久化的窗口布局；如果等视口接入后才处理 DPI，逻辑像素、渲染像素、鼠标拾取和保存的窗口位置会形成多套不一致的坐标。跨显示屏还会在窗口拖动、热插拔、睡眠恢复和系统缩放变化时触发运行期迁移。这个模块先固定底层不变量，暂不声称已经支持所有平台。

## 坐标与缩放不变量

应用内部的布局、QML 属性、窗口尺寸和输入事件使用 Qt 的逻辑像素（DIP）语义；工程几何、网格坐标和物理单位完全独立，不经过屏幕缩放。屏幕物理像素只在渲染后端、截图和 GPU 资源分配边界出现。

`devicePixelRatioF()` 是每个窗口/屏幕的运行期比例，不能缓存为全局常量，也不能截断成整数。逻辑尺寸到渲染尺寸只在边界转换一次：`pixel = round(logical * dpr)`，并在同一渲染周期复用结果，避免宽高分别累积误差。鼠标位置先在 QML/窗口逻辑坐标中处理，进入 VTK 或拾取服务时再按当前窗口 DPR 转为像素；业务服务不接收未经标注的“屏幕像素”。

Qt 6 的高 DPI 行为由 Qt 统一管理，不在业务代码重复乘缩放比，不手工设置 Qt 5 时代的高 DPI开关。缩放舍入策略在应用入口固定并记录；实施时验证 Windows 125%/150%、macOS Retina 和 Linux fractional scaling，不能用开发机的单一 1.0 DPR 推断正确。

## 屏幕与窗口状态模型

C++ `DisplayService` 负责观察 `QGuiApplication::screens()`、主屏幕和窗口的 `screenChanged`、DPI、geometry 与 availableGeometry 变化，向 ViewModel 发布不可变的显示配置快照。QML 只消费逻辑尺寸、可用工作区和当前显示 ID，不直接调用平台 API；VTK 适配器消费窗口 DPR 和像素视口。

显示 ID 按“平台序列号 → 制造商/型号/名称 → 稳定的几何与连接信息”逐级生成，不能把 `QScreen*` 指针或屏幕数组下标持久化。ID 只用于恢复提示和最近使用显示的匹配，永远不能成为工程数据或求解协议字段。屏幕断开、睡眠恢复或 ID 改变时，窗口回退到当前主屏幕的可用工作区。

窗口持久化保存逻辑尺寸、最大化/全屏状态、最后显示 ID 和相对工作区锚点；不保存未经解释的物理像素矩形。恢复顺序固定为：读取状态 → 匹配显示 → 以 availableGeometry 裁剪 → 应用最小尺寸 → 再恢复最大化/全屏。窗口至少保留一个可交互标题栏区域在可用工作区内；保存失败保留内存状态，不损坏上一份设置。

窗口跨屏移动或系统缩放改变时，不销毁 QML 引擎、不重建 ViewModel、不重载工程。Theme 使用逻辑尺寸重新计算，VTK 只重建受影响的像素 framebuffer/viewport；当前相机、选择集、网格和求解状态保持不变。DPR 变化期间合并连续事件，在下一渲染帧原子发布新配置，避免一半控件使用旧比例、一半视口使用新比例。

## 图形与输入边界

QML 场景尺寸、字体和间距由 Theme token 以逻辑像素表达；字体和图标资源按 Qt 的设备像素策略选择，不在组件里硬编码 DPR 分支。VTK/Qt Quick 合成使用窗口当前 DPR，渲染目标大小取窗口像素尺寸，UI overlay 与 3D 视口共享同一窗口快照。

截图、离屏渲染和导出明确接受目标 DPR 或物理像素尺寸，不能偷偷读取当前主屏幕比例。导出结果中的工程几何和数值不随显示屏改变；只有像素图像尺寸受导出选项影响。

触控、鼠标和高精度指针事件保留 Qt 提供的浮点逻辑坐标。坐标转换服务记录输入窗口、DPR、viewport 和相机版本，拾取结果回到工程坐标后才交给业务层；不能用屏幕坐标直接索引网格。

## 验证与平台矩阵

自动测试使用可注入的显示配置快照覆盖 1.0、1.25、1.5、2.0 DPR，窗口恢复裁剪、显示缺失、DPR 变化合并、逻辑到像素的舍入以及往返误差。ViewModel/服务测试不伪造 `QScreen` 私有状态，而验证公开快照和不变量。

真实窗口验证至少覆盖 macOS Retina 外接普通屏、Windows 混合 DPI（设置服务%/150%）和 Linux fractional scaling；检查拖动跨屏、热插拔、睡眠恢复、最大化/全屏、字体长文本、VTK viewport、截图和鼠标拾取。CI 没有第二块屏幕时记录为未覆盖，不能把 offscreen 通过写成多屏通过。

## 取舍与边界

不把屏幕 DPI 当作工程物理单位，也不为每个平台维护独立的布局算法。平台特有的工作区、刘海/菜单栏和全屏策略集中在 Qt 适配层；业务层只看统一快照。显示管理不依赖 QML 热重载，也不改变工程文件格式或几何物理单位。
