# 导入窗口与请求回执

[模块导航](README.md) · [UI 与 Bridge](../architecture/ui-and-bridge.md) · [资产激活](asset-activation.md)

## 当前交互

导入窗口使用 QML 属性、输入校验与 ViewModel 请求回执组织流程。用户选择文件、单位和网格类型；STL 预检返回几何摘要、资源提醒或结构化错误，当前有效预检完成后才允许确认。表单候选值不是已经提交的工程数据。

修改输入、重新选文件或关闭表单时使旧预检失效。完成通知携带请求身份，界面只接受当前请求的结果，不能用动画结束、按钮点击或本地 pending 变化推断成功。不引入额外 Qt 状态机或通用流程框架。

## Rust 提交闸门

`ProjectService` 检查来源快照、导入选项、工程会话与修订，负责资产写入和工程清单提交。预检成功仅表示该输入可继续，不代表导入已经完成；只有 Rust 发布成功结果后，QML 才刷新已保存资产与活动文档。

当前 STL 预检与确认导入均使用后台请求；QML 通过 `beginImportStl` 提交，并按请求编号接收完成回执。失败保留此前有效工程和网格；关闭表单请求取消，Rust 在工程清单提交闸门前检查取消。提交已经完成时不能靠关闭表单撤销，迟到结果仍按请求相关性规则处理。

## 界面与生命周期

普通输入与启用条件优先采用属性绑定；命令通过显式信号和方法传递。中文错误摘要由稳定诊断码适配，原始文件名和底层 detail 保持原值。长路径、错误反馈、键盘焦点、普通关闭和在途操作的限制应清楚可见。

QObject parent 与带上下文的连接管理所有权，后台完成结果不得引用已销毁窗口。GUI / 引擎销毁时停止投递，由 Rust 请求拥有者完成取消和资源收尾；不跨引擎搬运 QObject、JS 值或裸指针，也不因重新创建窗口重放提交命令。

## 验证

检查空输入、非法来源、选项改变、连续点击、旧请求乱序完成、预检取消、表单关闭和提交失败。通过实际请求回执断言命令只提交一次，失败保留旧资产，重新打开表单不会误用旧预检。布局与可访问性测试和真实 VTK 窗口验收分别记录。
