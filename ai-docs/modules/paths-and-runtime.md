# 跨平台路径与工程会话

[模块导航](README.md)

更新日期：2026-10-20。

## 边界

这里只描述应用内路径授权、工程会话和后台请求的相关性。路径服务不执行脚本，也不提供虚拟机、通用变量环境或任务框架。

## 路径层

| 类别 | 当前契约与实现 |
|---|---|
| 工程资产 | `project:/...` 绑定工程包根，不依赖 cwd。工程操作根据当前工程身份确定包根。 |
| 宿主标准目录 | `native/qt-adapter` 提供 Qt 标准目录查询；当前工程默认位置使用 Documents。未建立应用级配置、缓存或会话根的注入服务。 |
| 内置资源 | `qrc:` 是只读类别，Rust 路径服务拒绝把它解析成本机路径；Qt 资源通过 Qt 入口读取。 |
| 临时工作目录 | 当前没有通用的任务临时目录管理器；核心路径类型中的 `session` 类别不代表宿主已经创建并注入该根。 |
| 外部导入文件 | 本机路径或 file URL 通过显式导入流程读取；来源快照与工程内资产分开保存。 |

`panta-core::path` 定义 `project`、`user-config`、`app-data`、`cache`、`session`、`qrc` 六类根，使用 `scheme:/relative` 结构化引用，并提供三种解析：

- `resolve` 只校验引用并拼接绝对路径，不访问文件系统。
- `resolve_existing` 要求目标存在，规范化后仍位于对应根目录内。
- `resolve_write_target` 允许目标尚不存在，但要求最深现存祖先仍位于根目录内。

逻辑资源路径拒绝空值、NUL、绝对路径、越界 `..`、Windows 保留设备名、尾随点或空格及反斜杠；文件系统层检查 symlink / junction 是否越界。这是工程根授权协议，不是对恶意并发文件系统修改的安全隔离；引用、包含关系与符号链接回归在 `crates/panta-core/src/path.rs`，实际资产读取见 `activation.rs`。

Qt ViewModel 只负责本机路径 / file URL 适配和 `QString` 到 UTF-8 的可往返校验；file URL 通过 `QUrl::toLocalFile` 解码一次。Rust 核心服务直接执行工程资产路径校验，不再经 CXX 公开一套逻辑路径服务。逻辑引用不是 QML URL handler，不能直接交给 QML 或操作系统打开。大型数据通过资产 ID 或拥有式快照传递。

## 工程会话与后台请求

`ProjectService` 拥有工程会话和当前文档工作区；成功创建或打开工程后更新会话，关闭页签或替换工程时使不再有效的加载请求失效。后台请求捕获 generation、记录身份与 attempt，完成时由服务重新核对，迟到结果不能覆盖新工程或恢复已关闭的资产。

GUI 创建、打开和保存采用拥有式后台 I/O 请求：begin 表示准入，request 在后台 wait，服务线程 finish 校验作用域并发布结果。准入不表示成功，失败保留旧工程；C++ 不向 Rust worker 传 QObject，CLI 同步入口复用同一领域事务。

只读资产激活单独检查取消、容量和结果相关性，见[资产激活](asset-activation.md)。写入型操作通过 Rust 的提交闸门裁决，取消和窗口关闭不能撤销已经进入的原子写入；实际行为见[工程存储](../architecture/application-and-storage.md)。

路径适配不构成任意写盘、进程启动或网络授权。服务通过值对象或拥有式快照传递数据，不将 Qt 对象、JS 值或借用缓冲区放入后台请求。界面重建不得重放提交命令。

## 验证

路径测试覆盖引用校验、越界、symlink / junction、编码与 URL 转换；工程与加载测试覆盖 generation / attempt 过期、取消、失败保留和资源释放。路径检查通过不代表工程写入成功，也不替代打包、安装及真实窗口验收。
