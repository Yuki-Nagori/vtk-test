# 已保存资产的加载与激活

[模块导航](README.md) · [工程存储](../architecture/application-and-storage.md) · [导入交互](import-interaction.md)

## 当前范围

`ProjectService` 负责已提交 STL / Mesh 资产的按需读取、校验与驻留缓存；后台读取与校验实现在 `crates/panta-core/src/activation.rs`，服务自有的激活协调器维护 generation 与取消令牌。打开工程先读取清单和资产摘要，选择未加载资产后才在后台读取 sidecar；VTK 消费已经准备好的显示快照，不解析工程文件或来源 STL。

实现采用直接的请求、后台读取和完成结果流程，不加载声明式流程文件，也不提供通用状态机执行框架。资产加载只改变运行期工作区和缓存，不修改工程清单、工程 revision 或 dirty 状态。

## 请求相关性与取消

请求捕获工程会话、generation、导入记录身份和本次 attempt。后台阶段拥有输入与结果内存，在读盘、解压 / 解码和校验的安全点检查取消；服务线程消费完成结果时重新检查相关性。切换工程、关闭页签、取消或更新的 attempt 会使旧结果失效，迟到结果不能覆盖当前选择或恢复已关闭的文档。

取消并不意味着强制中断当前文件系统调用。共享取消标志用于尽早停止后续工作；已读出的结果仍须通过完成时的相关性检查。C++ / QML 不通过停止计时器、关闭窗口或切换按钮状态裁决 Rust 请求是否成功。

## 校验、缓存与失败行为

sidecar 读取验证资产身份、摘要、编码布局和网格领域约束，限制展开容量，失败返回结构化诊断。v3 sidecar 经 `MeshAssetReader` 先校验头部与目录，再按数据块批量读取、并行解压校验，峰值内存约为解码结果加一个批次的压缩块；v2 sidecar 仍整段读取（COMPAT，见 task 011 / 012）。未通过校验的数据不进入驻留缓存，也不替换有效网格。

`ProjectService` 管理缓存预算、驻留身份与释放；ViewModel 只保留当前活动显示 DTO，不按文档复制第二份权威缓存。切换到已驻留资产可复用缓存；关闭文档和淘汰策略按实际引用生命周期释放。加载失败保留已有有效资产，清楚区分错误、取消和过期结果。

## Qt 与 VTK 边界

ViewModel 将准入、加载状态、完成结果和诊断投影为 Qt 属性与通知。大型网格的显示准备在后台持有不可变快照；GUI 线程只发布仍有效的 DTO。Qt / VTK / GPU 对象继续在所属线程创建、使用和销毁，不把 QObject 或借用缓冲区交给 Rust worker。

相机导航、输入和逐帧绘制留在 C++，不逐帧跨 CXX 取领域数据。关闭最后一个资产页签后保持空视口，不创建默认模型。

## 验证

回归验证实际 sidecar 的首次读取、缓存命中、容量限制、损坏输入、取消、工程切换、关闭页签、重复 attempt 和乱序完成。断言有效网格及工程状态在失败后保持，过期结果不会发布，关闭后的引用能够释放。真实窗口另验证显示切换、导航和图形资源生命周期，后台测试不能代替 GPU 窗口验收。
