# 本地测试作业与数据交付边界

[架构总览](README.md)

## 当前范围

本仓库不接入外部求解器或共享求解协议。本文保留耗时操作与数据交付的通用原则，服务 STEP 导入、体网格生成、修复及渲染测试，不定义求解器客户端、RPC 或云端作业平台。

## 请求与状态

真实工程请求捕获输入资产及 revision，明确准入、运行、取消和完成的语义。无可靠进度时显示不确定状态；终态由持有实际操作与事务结果的 Rust 服务决定，UI 不能从按钮、日志或动画猜测成功。

## 生命周期与失败

读取、解析和重库调用按各自安全点响应取消。工程切换、关闭及来源修订变化后拒收迟到结果；失败保留已提交资产。C++ adapter 管理 native 资源和异常转换，Rust 管理身份、提交与错误，Qt 对象留在其线程。

## 大数据交付

大型 Mesh 使用拥有式领域快照、批量 DTO 和工程 sidecar；不经逐点 UI 调用传输。临时结果先验证再发布，资源所有者负责失败清理。VTK/GPU 对象仅用于显示，不充当工程的唯一数据源。

## 验证

使用真实模型与受控错误输入覆盖成功、损坏、取消、过期结果和资源释放。合成字段或网格明确标为测试数据，不据此宣称物理计算能力；无头检查不能替代实际 GPU 窗口验收。
