# 模型、材料标签与结果数据组合

[架构总览](README.md) · [网格](mesh.md) · [可视化](visualization.md)

## 定位与当前能力

本仓库需要导入已经求解完成的数据并渲染，因此保留网格、区域材料、边界标签与结果场组合的设计。这里的 Study 表示模型及结果的关联上下文，不要求接入求解器执行，也不引入 Study 配置编辑框架或 DSL。

当前主链支持工程、STL 表面网格导入、资产持久化、按需加载和 VTK 显示。结果文件导入、材料 / 边界标签显示、字段选择和时间步播放属于后续实现，不能由底层网格类型或既有工程字段推断已经具备。

## 模型与结果关联

结果数据必须引用明确的网格资产与版本。材料标签绑定稳定区域 ID，边界标签绑定面、边或单元 / 节点分组；这些标签用于识别和显示已求解模型，不在本仓库重新执行物理计算。

| 数据 | 必须明确的语义 |
|---|---|
| 网格 | 资产身份、来源修订、坐标系、长度单位与节点 / 单元编号映射 |
| 材料与区域 | 区域 ID、材料名称或标识、来源与版本；名称相同不代表同一材料定义 |
| 边界标签 | 关联对象、分组身份、标签含义及来源；缺失标签不能猜测补齐 |
| 结果场 | 名称、标量 / 向量 / 张量类型、分量、节点 / 单元 / 区域关联、单位与缺失值规则 |
| 时间维度 | 时间步或帧索引、实际时间值与单位；静态结果明确为单帧 |
| 数据来源 | 来源文件、格式 / 版本、原始模型标识，以及文件提供的求解工具与工况信息 |

节点数、单元数或包围盒相同都不能证明两个网格可直接共享字段。格式转换若重排实体，必须保留显式编号映射；结果不匹配时报告诊断，不能按数组位置静默附着到另一版本网格。

## 导入与校验边界

后续导入流程先读取来源快照，再校验拓扑、关联数量、分量布局、单位与时间步一致性；完整校验成功后才发布模型 / 结果资产。失败、取消或过期请求保留已有有效模型和显示结果。大型字段按批量快照或受控分块传递，不让 QML 持有逐点数组。

材料、分析序列、Fill 与 Gate 等现有 Rust 领域字段和工程清单仍按其 schema 保存；已删除的 QML 编辑、Bridge 草稿及配置确认接口不因此恢复。现有字段也不能直接充当任意结果文件的完整模型，需要根据实际导入格式明确新增契约与验收案例。

## 显示职责与后续验收

Rust 管理资产身份、网格版本、字段关联、单位、时间步和来源；C++ adapter 完成格式 / 库转换，VTK 管理显示对象、着色、图例和逐帧绘制。QML 只表达资产、字段与时间步选择，不从显示数组反推领域关系。

后续验收使用有来源许可和已知预期的已求解数据，覆盖节点 / 单元 / 区域关联、材料和边界分组、单位、缺失值、静态 / 多时间步、损坏输入和网格版本不匹配。确认字段选择、范围与图例对应，切换时间步不串用旧字段；真实窗口另验收渲染与资源释放。合成测试场必须标注，不能作为求解正确性的证据。

## 自动化边界

实际工程与 STL 命令见[命令层](command-layer.md)；后续若增加结果导入或批处理命令，应复用同一资产校验与提交服务。无界面读取和真实 GPU 渲染分别验证，不因存在命令行入口就宣称已支持全部 headless 场景。
