# 应用平台、Rust 与工程存储

[架构总览](README.md)

路径授权与工程会话相关性见[路径与运行时](../modules/paths-and-runtime.md)，已保存网格的后台加载见[资产激活](../modules/asset-activation.md)。

## Rust 的职责

Rust 负责工程资产、场景文档、命令、异步操作与序列化，C++ 负责 Qt 桥接以及几何、网格和渲染的 native 实现。完整撤销/重做与插件仅作扩展参考，当前不接入外部求解器。

当前 `native/bridge/src/settings.cpp` 仅向 QML 暴露系统减少动态效果偏好 `reducedMotion`，平台查询由 Qt adapter 负责。中文文案直接声明；不存在语言设置、翻译目录或语言偏好持久化。Theme 仅保存固定 QML 视觉常量，不提供主题配置、切换或偏好存储。

应用服务将用户命令转换为跨模块操作；Rust 与 C++ 之间优先传递明确所有权的 DTO、句柄和结果。`ProjectService` 通过 [CXX](../standards/cxx.md) 落地最小 `ProjectService`：创建、打开、保存和重命名命令通过 `ProjectSnapshot` 传递，错误使用稳定 `project.*` 代码。字符串编码、缓冲区归属、释放接口、线程约束和错误映射必须明确，异常与 panic 不得未经处理跨越 FFI 边界；大工程操作仍需异步化。

工程模块按职责组织为 model（命令 / 状态 / 清单）、error（稳定诊断）、mesh_cache（驻留策略）和 service（会话编排），公共 `panta_core::project` 门面及 CXX 入口保持原路径。方案配置和导入仍由应用服务校验及提交；具体持久化和后台执行契约继续按对应任务推进。

工程 revision 是过期请求的相关性键，递增通过单一检查入口完成。达到 `u64::MAX` 后拒绝需要新修订的变更，在修改内存、写入资产或启动候选提交之前返回 `project.command_invalid`；读取和无操作请求保持原语义。不能以饱和成功让不同工程状态共享同一修订。

## 工程模型

当前工程组织元数据、导入记录与网格资产；后续结果导入需关联几何、网格版本、材料区域、边界标签和结果引用。Study 仅表示这些模型与结果的关联上下文，具体语义见[模型与结果组合](study-and-automation.md)。每个实体具有工程内稳定 ID，派生实体记录来源修订。模型状态与窗口布局、临时选中项等会话状态分开存储。

工程 dirty 状态来自已接受的领域变更。视口旋转是否持久化可以单独定义，不能让每一帧渲染都产生工程命令。已求解数据携带的工况与求解工具信息属于来源记录；本仓库不据此建立求解执行作业或 Study 配置编辑框架。

## 命令与后台任务

命令表示可验证的用户操作，后台任务承载导入、资产加载等执行过程，后续生成与修复复用相同的生命周期原则。任务有 ID、状态、进度、取消请求和错误；开始后使用输入快照，防止执行期间读取到不断变化的工程。

工程后台流程采用拥有式请求和完成结果，导入准备归 `panta-io`，工程提交归 `panta-core`。准备完成不等于提交成功；取消、迟到结果及工程关闭后的失效由 Rust 决定，Qt 只展示结果。[资产激活](../modules/asset-activation.md) 说明只读加载、取消与过期结果裁决；工程写入仍使用独立的提交闸门。

私有有界后台执行器承载工程预检、只读激活与元数据提交：读取最多 2 个 worker / 64 个在途请求，写入 1 / 32，满载立即拒绝。排队保存路径或冻结候选，worker 才开始读取与解析。激活的在飞记录和未消费结果总数上限为 256；这些是数量限制，不能替代输入字节或内存预算。具体实现见 `crates/panta-core/src/`。

工程服务销毁时取消预检，使旧激活代次失效并释放结果；已接受的清单写入保留后台候选和事务回执，宿主销毁只停止 UI 投递。事件循环退出且 QML 引擎销毁后调用 `finish_background_writes` 关闭写入准入并收尾。C++ 安排生命周期，Rust 决定提交与取消；正常退出收尾不保证断电或异常结束的持久性。

后续撤销/重做若接入，应围绕工程模型变更设计。大型资产可以保存引用或修订，避免每步复制整个网格；运行期任务取消与已提交资产引用的撤销分别定义，不将撤销当作中断后台操作的手段。

## 存储契约

完整工程容器尚未定型。工程服务的最小契约使用 `Documents/panta/<name>/<name>.panta` 目录包；当前 schema 4 将工程元数据、ImportRecord v4 和 `mesh_assets` 索引写入 `.panta`，Mesh payload 独立保存于 `assets/meshes/`，体网格导入携带的结果场保存于 `assets/results/`（task 029）。导入记录保存来源路径、名称、格式、源字节 SHA-256、mtime 与 size 作为诊断快照，不保留原始 STL 副本，也不在重开工程或加载 Mesh 时访问来源路径。当前开发阶段只支持 schema 4；schema 1–3 明确拒绝且不修改工程文件，实际迁移需求单独登记设计。工程保存通过写入租约及同目录临时文件替换主清单。该实现仍是最小工程契约，不代表完整工程格式。

工程写入由 Rust repository 租约协调，使用 fs4 文件锁覆盖同一工程的跨进程写入。争用返回 `project.command_invalid`，锁文件保持稳定。租约与清单替换前核对磁盘 revision，过期服务保留候选与旧磁盘内容；显式 unlock 后关闭句柄。该协议只协调遵守它的写入者，不拦截外部文件修改。

临时清单位于 `<name>.panta.write/`，按进程 ID / 序号使用 `create_new` 独立创建，碰撞有限重试；失败清理只针对当前租约拥有的临时文件。写入与 `sync_all` 成功后 rename 为提交点，其后更新内存已保存修订；解锁收尾及诊断不改变提交结果。Mesh sidecar 发布、清单提交与失败回滚共享同一租约。稳定锁文件及空 staging 目录保留在工程目录，不写入清单或作为资产展示；本实现保证文件内容同步，不承诺所有平台断电后的目录项持久性。

工程清单保留按导入记录 ID 索引的 `analysis_sequences` 覆盖表，缺省为 Fill，非默认值由 Rust 校验并事务保存；当前 QML / Bridge 没有编辑或确认此配置的接口。`imports[].mesh_type` 是用户选择的配置，不表示已生成分析网格。project 在本仓库首先是模型资产与场景载体，独立 Study 和求解执行不属于当前验收范围。

`.panta` 保存元数据与资产索引，Surface / Volume Mesh payload 旁置在可移交工程目录中。索引以稳定 asset ID、revision、摘要和工程内相对路径寻址，显示名称独立于身份。页签激活由 Rust 按需解码验证 Mesh，再通过批量 CXX DTO 创建 VTK 对象；mapper、actor 和 GPU 资源不持久化。来源文件可移动或删除；sidecar v3 保留 f64 顶点与毫米单位，分块压缩并逐块校验，资产摘要覆盖目录（含块摘要）；v2 只读兼容。详见[网格资产边界](mesh.md)与 `crates/panta-mesh/src/asset/mod.rs`。

资产文件使用不可变 revision 名称。新导入在写入租约内先创建临时 sidecar、同步并发布文件，再原子提交引用它的新 `.panta`；提交失败会清理本次候选文件并保留旧清单。未引用 sidecar 不会被当作已提交资产。相对路径与符号链接包含性校验使整个工程包可移动且拒绝越出工程根的引用。单文件原子替换不代表多文件断电事务；目录项断电持久性仍不承诺。

需要明确嵌入资产与外部引用策略。便携工程应包含必要资产或可解析的相对引用；只保存开发机绝对路径不能作为默认可移交方案。读取时对缺失资产、未知 schema 版本、损坏数据及单位不一致提供明确诊断。

保存采用临时写入、完整性检查和提交步骤，使失败不会损坏上一份有效工程。多文件工程需要整体提交或可恢复机制，单个文件原子替换不等于整个工程事务完成。不预先实现多版本 reader 或自动迁移；遇到不支持的格式版本明确拒绝并保留原始数据。确有现实迁移需求时单独建 task，遵循 [兼容例外规范](../standards/code-lifecycle.md)，迁移过程保留原始文件或可恢复副本。

## 大数据与缓存

Mesh、结果按用户打开的页签、时间步、区域或字段延迟读取，缓存有容量与失效策略。缓存可由已提交资产重建，不能作为唯一数据源。关闭页签释放该页签独占的 CPU Mesh 快照和 VTK 显示对象；关闭工程时取消读取、释放映射和资源。结果文件仍在写入时，仅开放已经正式发布的完整片段。Mesh 快照容量和逐出阈值由资产激活和 sidecar 的代表性测量确定，不由 GPU RSS 单项推导。

验收重点是保存/重开后 ID 与引用一致、资产缺失可解释、写入失败保留旧工程，以及旧任务不能污染新打开的工程。
