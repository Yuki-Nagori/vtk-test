# 注释与接口文档规范

更新 / 查阅日期：2026-09-16。适用于所有自有代码；下面区分工具机制与项目规则，文档生成工具尚未配置。

## 官方依据

Rust 使用 `///` 记录条目文档，`//!` 记录包含它的模块或 crate 文档，支持 Markdown 与示例。[rustdoc](https://doc.rust-lang.org/rustdoc/how-to-write-documentation.html)

Doxygen 支持特殊注释块与接口描述；使用其格式不代表构建时已经生成 API 文档。[Doxygen docblocks](https://www.doxygen.nl/manual/docblocks.html)

## 注释写什么

- 解释代码不容易表达的原因、约束和取舍，特别是单位、公差、坐标系、索引起点和局部节点顺序。避免把代码逐句翻译成自然语言。
- 公共 API 说明输入输出、可恢复失败、资源所有者、借用有效期及线程要求；只写与该接口实际相关的条目，不为简单 getter 填满空字段。
- 算法说明适用条件与关键不变量；来自论文或上游缺陷的实现附可定位出处，不能只写“参考网上实现”。
- 对性能优化说明测量依据与代价。临时 workaround 说明触发版本、上游 issue 或对应 task，以及何时可以移除；承担兼容行为时必须额外遵守 [代码生命周期规范](code-lifecycle.md) 的 COMPAT 标记要求。
- 修改行为时同步注释和示例。删除无效注释、被注释掉的旧代码、作者/日期流水账；历史由 Git 和任务记录保存。

项目文档与解释性注释默认使用中文，标识符和 API 名保留原文。与上游同步的代码保留其既有语言，不为统一注释语言改写第三方源码。这是项目约定，不是语言要求。

## C++ 与 Qt/QML

公共头文件使用简洁 Doxygen 风格；实现文件用 `//` 说明局部原因。声明处维护完整契约，定义处只补实现细节，避免两份契约漂移。

`#include` 列表按 `.clang-format` 排序：主头 / 契约头独立置顶，其余头文件按规则分组排序。直接声明实际使用的依赖，不靠偶然的传递包含；第三方头确有顺序或平台约束时，在局部解释原因并通过真实编译验证。

```cpp
/// 将候选网格发布到当前工程。
/// 输入坐标为米；仅在输入修订仍有效时提交。
/// 仅由应用服务线程调用；成功后工程持有网格，失败保留旧资产。
```

示例只展示注释格式，具体 API 必须准确描述实际移动/共享方式，不能用“持有”掩盖不明所有权。Qt 信号说明触发条件与携带 ID，跨线程调用说明队列交付方式；QML 公共属性/信号附近写输入输出与绑定约束。无需给每个控件和布局属性添加解释。

CMake 注释说明非默认选项、依赖限制和生成步骤的原因，不注释“这里链接一个库”。生成的 CXX/Qt 文件不手工添加注释，修改生成输入或手写 adapter。

## Rust

Rust 公共业务 API 使用 `///`；按需增加 `# Errors`、`# Panics`、`# Safety`、`# Examples`。公开 unsafe 接口必须解释调用方义务；每处 unsafe 块用 `// SAFETY:` 说明这些前提为何在此成立，不能只写“这是安全的”。示例具备环境要求时明确说明，不为让检查变绿随意标记 ignore。

## TODO / FIXME 与维护

仅对明确的后续工作保留标记，建议格式为 `TODO(task NNN): 原因；完成条件`；NNN 必须指向真实任务。尚无编号则先建 task，不能引用不存在的占位编号。阻止当前任务验收的缺陷必须修复或明确阻塞，不能靠 TODO 伪装完成。

评审时检查注释是否仍准确、是否交代所有权/线程/单位、任务引用是否有效。注释不能替代可验证的边界检查或类型约束。

必要兼容入口必须标记 `COMPAT(task NNN; remove-task MMM): ...`，并提供真实任务、适用条件与删除条件；普通 TODO/FIXME 不能代替该标记。格式与搜索方式统一见 [代码生命周期规范](code-lifecycle.md)。
