# 验证、变更与评审规范

更新日期：2026-10-20。以下是本仓库工作约定；统一测试与 CI 入口以根 Cargo aliases、`tests/` 和 `.github/workflows/ci.yml` 为准。

## 变更范围

先在 task 中说明触发条件、预期行为和非目标。实现围绕任务完成，不混入无关重构、大范围格式调整或依赖升级。必要的长期决策同步架构/规范，不只留在任务完成摘要。

每次 commit 执行 [提交规范](commits.md)，检查实现、测试、配置、文档与 task 一致。PR 描述汇总最终行为和验证，不代替逐个 commit 的完整性检查；保留其他人的已有更改和暂存状态。

## 验证层次

| 改动 | 最小有意义的验证 |
|---|---|
| 文档/忽略规则 | 链接与索引；忽略正反样例；diff 空白检查 |
| 领域逻辑/错误处理 | 关键输入、失败、状态与修订行为 |
| 构建/依赖 | 干净及增量构建、配置切换、失败码 |
| FFI/异步 | 所有权、错误、取消、关闭后的迟到回调 |
| 几何/网格转换 | 单位、索引、拓扑/边界映射与无效输入 |
| QML/渲染 | lint、资源加载、真实窗口与图形生命周期 |
| 存储/协议 | 往返、版本不兼容、部分写入与失败恢复 |

选择能发现行为回归的测试，避免测试只复述实现。简单可逆的文档改动不新增框架；故障修复优先添加能复现问题的最小用例。测试随机性需要可重放输入，不默认引入不必要的统计波动。

当前以关键行为、错误路径与资源生命周期回归验收，不设覆盖率百分比门禁。QML 使用可执行绑定和关键状态行为测试；测试通过不能替代独立评审与真实窗口证据。

未验证路径先区分可达逻辑、难触发系统故障与有证据的不可达代码。可达逻辑补行为测试，系统故障采用可控测试接缝并记录剩余缺口；低风险和低频不是排除理由。每个实际工具抑制须登记理由、配置位置、替代验证与复查条件，详见[质量工具链模块](../modules/quality-tooling.md)。测试优先清晰断言与失败诊断，不吞掉夹具创建或任务提交失败，不为数字删断言或重复调用 API。真实窗口、GPU、线程和 ABI 检查作为独立证据。

## CAE 样例与断言

样例记录来源、分发许可、单位、坐标系及预期实体/分组。浮点比较声明绝对/相对容差及理由；不能用放宽阈值掩盖失败。网格生成可能存在顺序差异，优先验证语义与不变量，而非无依据地要求字节完全一致。

图形截图检查需固定有意义的场景和环境；不能用一次无头测试代替所有目标平台的 GPU/窗口验证。性能宣称附输入规模、机器、配置和测量方式，没有数据时只写待验证。

## 结果与评审

记录实际命令、cwd、平台/工具版本、退出结果和主要证据；区分通过、失败、跳过与未覆盖。必需验收未通过时不能标 done，不能把缺失测试入口当作成功。

评审按变更关注：行为是否符合 task；失败是否保留有效状态；单位/线程/所有权是否清楚；构建产物和样例是否归位；注释和文档是否同步。详细接口注释遵循 [注释规范](comments.md)。不要求每个小改动重复一份与风险无关的全栈检查清单。

清理检查覆盖旧符号、调用点、构建注册、依赖、配置和文档；不得关闭 dead-code 告警来保留旧实现。兼容标记及移除条件按 [代码生命周期规范](code-lifecycle.md) 复核，例外条件已结束时及时删除。
