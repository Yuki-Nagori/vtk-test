# Ninja 构建执行规范

更新日期：2026-10-20。适用于现有单配置 Ninja 构建；工具版本和供给方式见依赖清单。

适用于 CMake 生成的 Ninja 构建，Ninja 不拥有项目依赖选型或用户配置。

## 官方依据

Ninja 侧重快速执行由更高层工具生成的构建图，图中区分输入、输出与依赖；其设计不鼓励把复杂配置策略放进手写构建文件。[Ninja Manual](https://ninja-build.org/manual.html)

## 项目规则

- 由 CMake 生成 Ninja 文件，不手工维护或提交 `build.ninja`。修改构建行为回到 CMake 或 Cargo 调度层。
- 采用普通（单配置）Ninja：配置由 preset 的 `CMAKE_BUILD_TYPE` 固定，Debug/Release 以独立构建目录隔离；launcher 定位与增量路径因此无需 `$<CONFIG>` 展开。
- 优先通过 `cmake --build` 调用，Ninja 命令仅用于诊断。本仓库选择普通 Ninja；调整生成器前先明确配置目录和 launcher 定位方式，并验证切换行为。
- 总并行度由编排层协调，避免 Cargo 与嵌套 Ninja 各自占满 CPU/内存。为大型链接或代码生成限流时记录证据和配置来源。
- 生成文件必须声明完整依赖，删除单个产物后应可重建。不得用“每次先 clean”掩盖缺失依赖。
- 保存失败命令和退出码；不要把重试成功当成图正确的证据。共享构建目录需避免多个独立 configure/build 进程争用。

## 验证

重复构建应不执行不必要的编译；修改公共头触发相应消费者，修改单个实现不重编无关模块。记录一次受控并行构建与失败恢复，不在无测量条件下承诺构建耗时。
