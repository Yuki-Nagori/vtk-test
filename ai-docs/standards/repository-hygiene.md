# 仓库文件、产物与忽略规则

更新日期：2026-10-20。适用于代码、构建配置、样例和本机产物；当前构建产物由 Cargo 与 native 供给链集中写入 `target/`，新增路径时同步维护忽略与清理规则。

## Git 行为依据

`.gitignore` 针对未跟踪文件，不会让已跟踪内容自动退出版本控制。否定规则也不能恢复被整个父目录排除的文件；共享规则、本机 exclude 与全局规则有不同用途。[Git gitignore](https://git-scm.com/docs/gitignore)

## 文件归属

| 文件类别 | 项目约定 |
|---|---|
| 源码、QML、资源、schema | 提交；生成输入必须可追溯 |
| Cargo.lock、工具链、共享 CMake presets | 提交；保持可复现 |
| CMakeUserPresets.json、本机环境覆盖 | 不提交；示例可提交，不能包含个人路径 |
| 编译/生成的 CXX、moc、rcc 文件 | 放构建树，不手工维护或默认提交 |
| 小型测试夹具 | 放根 `tests/fixtures/<module>/` 的明确路径，记录来源、单位及预期 |
| 临时工程、网格和仿真结果 | 放根 `.local/` 或工作区外 |
| 日志、截图、测试报告、包产物 | 放根 `artifacts/` 或构建目录 |

## 换行约定

根 `.gitattributes` 使用 `* text=auto eol=lf`：项目文本在索引与检出中统一 LF，Git 自动识别的二进制保持原始内容。确定性输出夹具直接比较字节，不在断言前归一化换行。Git 属性变化影响检出及测试输入，CI 按代码配置变更执行检查。

## 目录与规则维护

Cargo workspace 默认产物在根 `target/`；CMake 使用源码树外目录，如根 `build/` 或 `native/build/`。Cargo build script 遵守 `OUT_DIR` 约定，不因为此处列出 build/ 就允许脚本任意写源码树。

根 build/out/dist 与局部 native 产物目录被忽略；源码中名为 `build` 的业务目录不会被全仓库通配误排除。Qt/QML 与 CXX 的生成文件随构建树排除，不使用 `moc_*`、`*.h` 等宽泛源码匹配。

不全局忽略 `*.step`、`*.stl`、`*.vtk`、`*.vtu`、`*.json`、`*.log` 或二进制扩展名：这些可能是必要测试夹具。大型资产另定存储策略，不能通过添加忽略扩展名掩盖缺少样例。

`.vscode/` 不整体忽略，方便未来提交可移植的推荐设置；个人编辑器偏好放本机 exclude。`.env.example`、`.env.template` 可提交，实际本机覆盖文件忽略；忽略规则不是敏感数据清理机制。

## 修改前后检查

添加规则时同时列出“必须忽略”和“必须保留”的路径，用 `git check-ignore -v --no-index -- 路径` 检查匹配来源。`--no-index` 便于检查即使已经跟踪的路径会匹配什么，不会修改暂存区。

检查 `git status --short` 和差异，不擅自清理未跟踪文件或撤销其他工作。对已经进入版本控制的产物，另行确认归属再调整索引，不能期望新增忽略规则自动移除它。

升级工具或新增产物目录时同步规则与对应 task；不预先添加未采用的 Node、Java 等技术栈模板。

## 废弃内容

不建立 old/backup 等版本化目录保存被替换实现，也不以忽略规则把死代码藏在当前工作流程里。Git 保存历史，当前代码及其构建/配置/资源按 [代码生命周期规范](code-lifecycle.md) 同步清理；不要删除仍有用途的测试夹具或用户工程数据。
