# 文档与示例维护规范

更新日期：2026-09-16。以下是项目编辑约定，文档工具尚未接入自动检查。

## 结构与信息归属

遵循 [规范索引中的文档职责](README.md)：架构说明目标及边界，规范记录长期规则，task 保存工作范围与证据，索引保存状态摘要。目录入口用 README.md；任务是 `NNN-name.md`，不为单个文本建立子目录。

入口保持简洁，详细说明下沉到主题文件。相同版本表或规则只在一个位置维护，其他文档链接过去；移动文件时更新所有引用。外部仓库在标题和路由标明 `[External / 非本仓库]`。

## 写作与格式

- 文档使用 UTF-8，段落表达完整含义；列表用于真正并列或顺序内容，任务元数据使用无序列表。
- 表格用于比较和映射，不把长段落硬塞入单元格。标题与正文/列表之间留空行。
- 代码块标明语言；路径、命令、类型用行内代码。仓库文档中的文件链接使用相对于当前文档的路径，避免个人机器绝对路径。
- 内部链接文字说明目标内容；避免“点这里”。不要固定写文件数量、下一空闲编号等容易失效的信息，除非属于历史验证记录。
- 将“已实现”“规划”“候选”“待验证”分开表述。任务完成不自动意味着所有相关产品能力完成。

## 命令与示例

可执行命令需说明工作目录、前置条件和必要版本；示意命令明确标记，不能把多个命令缩写成一个不存在的入口。样例尽量小，包含失败时如何判断；不要嵌入真实个人路径、凭据或不可分发输入。

代码示例与真实接口保持一致。接口还未落地时写“示意”；不能为了展示结构伪造已存在的 target、crate 或测试结果。

## 来源与更新

技术机制引用官方文档或上游源码，链接放在相关事实旁；项目自己的选择标为项目约定。记录实际查阅日期，遇到浮动 latest/stable/nightly 链接，落地前核对所选版本。未重新阅读的资料不要仅为看起来新而修改查阅日期。

修改技术行为时同步相关规范和使用方法。文档-only 改动检查本地链接、路由覆盖、代码围栏、旧路径残留和差异空白；引用线上资料有变化时再做针对性核验，不把每次标点修改扩大为全网复查。

删除或替换功能的 commit 同步清理失效接口说明、命令、示例与路由；需要解释历史原因时在 task/Git 历史中记录，不保留一份看似仍可用的旧教程。每次提交的 task 更新遵循 [提交规范](commits.md)。
